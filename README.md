## How I Build

| Principle | Meaning |
|---|---|
| Backend truth first | Screens should represent real API behavior, permissions and persisted data. |
| Product before decoration | UI should make the workflow clearer, not hide missing logic. |
| Operational clarity | Admin tools should be editable, readable and safe for repeated use. |
| Shared rules | Web and mobile should follow the same product logic when they represent the same flow. |
| Useful documentation | Docs should map real code paths and product decisions. |
